# Disabled offline artifact verifier

This standalone qualification helper has no RPC client, publisher, wallet DB access,
or connection to the service's publication gate. A successful report applies only
to the supplied files. It does not qualify the live adapter or extraction recovery.

The bounded profile is NU6.3 regtest, V6, Ironwood-only, two through eight actions,
exactly one positive sender input and recipient output, and independently checked
positive change outputs at the pinned sender's internal diversifier zero. Actual
Zallet defaults split change into four notes; each is checked and summed. Fees use
the actual action count, with no relaxation of note/ciphertext/authorization checks.

CLI inputs are `--intent` (the service's intent JSON), `--pczt` (binary completed,
signed PCZT), `--trusted-wallet` (private bootstrap JSON below), `--tip-height`
(observed regtest height), and optional `--raw` (binary Zallet extraction response).
Without raw bytes, the helper validates a locally extracted artifact and explicitly
reports `raw_response_verified: false`; locally generated bytes are never emitted.

Use `--effects-only` for created/proven artifacts: public parsed-note checks verify
input ownership, nullifiers, randomized keys, value/note commitments, exact output
ciphertexts/memos/change and policies. This mode performs no local extraction or
circuit-key construction and explicitly reports authorization as false. It cannot
accept `--raw`; it does not prove chain membership or spendability.

```json
{
  "wallet": "sender",
  "account": "00000000-0000-4000-8000-000000000001",
  "ufvk": "uviewregtest1...",
  "registration_address": "uregtest1...",
  "registration_index": 0,
  "nu6_3_activation_height": 1
}
```

The bootstrap file must come from the newly provisioned disposable wallet, be
stored privately, and be bound to the indicated account before accepting intents.
The helper's local parameter object supplies regtest encodings and fee APIs; it
does not authenticate a node's activation schedule or the supplied tip height.
The caller must independently check the exact qualified node schedule before
construction and submission. The artifact itself must use V6 and NU6.3 after the
bootstrap's NU6.3 activation height. No viewing material belongs in arguments.

Use the pinned lockfile with `cargo run --locked --manifest-path verifier/Cargo.toml
-- --intent ... --pczt ... --trusted-wallet ... --tip-height ... --raw ...`.

The helper fails closed on incomplete notes, unrecognized shape, extra outputs,
wrong recipient/memo/fee/expiry, invalid authorization, or mismatched final bytes.
See `../docs/payment-verifier-design.md` for the complete design and qualification
gates. Compilation and real-fixture outcomes are recorded separately; this file
does not assert either succeeded.
